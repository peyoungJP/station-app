# 1. 事業の北極星

## 1.1 本質的な目的

> 物理空間に、黒板のような"ゆるくて温度のあるデジタル掲示板"を置く

駅は象徴であり、本質は「場所に紐づくコミュニティ空間」である。

---

# 2. 戦略の再定義（都市型から地方実証型へ）

## 2.1 旧モデル（スケール前提）

* 全国駅常設掲示板
* ASO中心
* 路線集中突破
* DAU1,000→10,000→50,000

## 2.2 新モデル（実証優先）

> イベントで密度を作り、常設へ拡張する

理由：

* 地方では日常密度の形成が困難
* イベントは自然発生的に密度が生まれる
* 実証コストが低い

# 3. プロダクトの方向性

## 3.1 既存アプリからの拡張方針

現在のアプリは「駅」に紐づく掲示板だが、事業戦略上は「場所」に紐づく掲示板へ拡張する。

```
Location（場所）
 ├─ station（常設 … 現在のアプリそのもの）
 ├─ event（期間限定 … 森道・花火などのイベント会場）
 └─ area（将来拡張）
```

この拡張に伴う技術仕様（データモデル・テーブル設計・画面仕様）は `SPECIFICATION.md` に記載する。
本書では「なぜ拡張するか」「何を検証するか」に集中する。

## 3.2 Web版の位置づけ

イベント実証ではQRコードから直接アクセスできるWeb版が必須。

* **目的**: フェス参加者がアプリをインストールせずに使えるようにする
* **スコープ**: QR直リンクで特定イベントの掲示板を閲覧・投稿できれば十分
* **位置情報検索は不要**（QRで直接ページに飛ぶため）

Web版の技術選定・画面構成・URL設計は `SPECIFICATION.md` に追記する。

### QR接触導線（会場内外）

物理的な接触ポイントを複数確保する。

```
■ 最優先（自分だけで実行可能）
  1. 自分のスマホ画面にQRを常時表示
     → 会場内で「これ面白いんですよ」と見せる（1対1の草の根）
  2. ステッカー（5cm四方）を自分の荷物・テントに貼る
     → Canvaでデザイン → コンビニシール印刷（約500円）
  3. X投稿に毎回QR画像を添付

■ 推奨（少し準備が必要）
  4. A6フライヤー 100枚（ラクスル等で約3,000円）
     → 会場内で自然に手渡し or 座席付近に置く
  5. 知人3〜5人にもQR画像を共有 → 各自のSNSで拡散依頼

■ 発展（運営協力が得られた場合）
  6. 会場内の掲示板・案内板へのQRポスター掲示
  7. 公式SNSでの紹介
```

### 運営への問い合わせについて

**結論: 問い合わせることを推奨する。ただしハードルを下げた形で。**

理由:
* 拒否されても失うものはゼロ
* 「混雑分散に寄与」は運営にもメリットがある
* 許可を得れば会場内でのQR掲示が可能になり、リーチが大幅に拡大

**問い合わせメール文案:**

```
件名: 【有志企画】森道の混雑情報共有ツールのご相談

つきまして、以下についてご相談させていただけないでしょうか。

・会場内でのQRコード付きフライヤーの配布（小規模）
```

**問い合わせ判断のタイムライン:**

## 目的

* 家族層の利用検証（森道とは異なるユーザー層）
* 実用性（混雑・トイレ・駐車場情報）の検証

## KPI

| 指標 | 成功ライン | 森道との差異の根拠 |
|------|-----------|------------------|
| Web訪問 | 200以上 | 花火は滞在時間が短く（2〜3時間）、スマホ操作の余裕が少ない |

* **実用情報に特化**: 「おすすめ」より「駐車場空いてる？」「トイレどこ？」
* 固定スレは実用系を多めに:
  1. 「駐車場の空き状況」
  2. 「トイレ・自販機の場所」
  3. 「穴場スポット」
  4. 「帰りの渋滞情報」
  5. 「雑談」
* 森道の実証結果を反映してUI・導線を改善

# 11. リスク管理

| リスク | 発生確率 | 影響度 | 対策 |
|--------|---------|--------|------|
| 投稿ゼロ（コールドスタート） | 高 | 致命的 | シード投稿30件 + 知人3〜5人の協力 + 自分が最初に書く |
| 荒らし・不適切投稿 | 中 | 高 | 通報機能 + NGワードフィルタ + 投稿レート制限 + 当日手動巡回 |
| 密度分散（複数イベント同時） | 低 | 高 | 同時展開禁止。1イベントに全集中 |
| 運営からの拒否・停止要請 | 中 | 中 | 会場外戦略に切替。X + 草の根に集中 |
| 思想崩壊（実用一辺倒になる） | 低 | 中 | 「雑談」「感想」スレを温度のある投稿の受け皿として維持 |
| 個人情報の書き込み | 中 | 高 | 利用規約で禁止 + 通報→即削除フロー |
| 森道の日程が5月でない・中止 | 低 | 高 | 蒲郡花火を最優先に切替。実証時期を7月にスライド |
| 週5時間で開発が間に合わない | 中 | 高 | Web版のスコープを最小限に絞る。デザインより機能優先 |

# 13. Go / No-Go判定

## 森道終了後

### Go条件（→ 花火実証に進む）

* 投稿100以上
* 同時接続30以上
* 再訪率20%以上

### Partial条件（→ 改善して花火実証に進む）

* 投稿20〜99
* 同時接続10〜29
* → 改善点を特定し、花火でリトライ

### No-Go条件（→ ピボット検討）

* 投稿20未満
* 同時接続5未満
* → 「人がいても書かない」なら投稿動機の仮説が間違っている
* → 完全イベント特化（投稿ではなく情報配信型）への転換を検討

No-Goは失敗ではなく仮説修正。

# 14. 進化シナリオ

## 成功（Go）

* 他の地方フェスへ横展開（例: 各地のクラフトフェス、音楽フェス）
* 地域イベント掲示板モデルの確立
* 常設駅黒板への自然拡張

## 部分成功（Partial）

* 実用情報特化へ進化（混雑・トイレ・駐車場の可視化ツール）
* イベント情報ポータルへのピボット

## 失敗（No-Go）

* 投稿動機の再設計（匿名テキストではなくスタンプ？リアクション？）
* 掲示板ではなくリアルタイム投票型への転換
* 撤退（損失は約4万円）
